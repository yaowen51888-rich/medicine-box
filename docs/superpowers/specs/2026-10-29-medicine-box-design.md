# 家庭药箱效期提醒 App — 设计文档

日期：2026-10-29
状态：已与用户确认设计方案

## 1. 背景与目标

给老人备药的家庭的真需求：药箱里的药放着放着就过期了，过期药吃了有害，扔了又不知道哪些过期。

**目标**：手机拍照 → AI 自动识别药名和有效期 → 到期前醒目提醒该扔的药。

**成功标准**：
- 拍一张药盒照片，10 秒内完成一条药品记录（含自动识别的药名+效期）
- 打开首页一眼看清：哪些已过期（红）、哪些 30 天内到期（橙）、哪些正常（绿）
- 无后端、无账号、无构建，纯静态文件可直接部署

## 2. 已确认的关键决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 平台形态 | 手机网页 App | 无上架门槛，链接即用，开发最快 |
| 录入方式 | AI 视觉识别 | 拍照自动填药名+效期是核心体验 |
| 数据存储 | 本机 IndexedDB | 无后端、无登录，子女自己管理老人药箱够用 |
| 技术方案 | 纯前端无构建（vanilla JS） | 依赖最少，维护成本最低 |

## 3. 页面设计（4 屏，hash 路由单页应用）

### 3.1 药箱首页 `#/`
- 顶部统计条：共 N 盒 · 过期 X · 30天内到期 Y
- 药品列表按状态分三段：
  - **已过期**（红色）— 剩余天数为负
  - **即将过期**（橙色）— 剩余天数 ≤ 提前提醒天数（默认 30，可设置）
  - **正常**（绿色）
- 每条显示：缩略图、药名、效期（YYYY-MM-DD）、剩余天数（如"剩 15 天"、"已过期 3 天"）
- 剩余天数 = 效期日 − 今天（日期差）：效期当天为「剩 0 天」算即将过期；负数为已过期
- 底部悬浮「+ 拍照录入」按钮
- 默认只显示 `status = "active"` 的药；已处理的在详情操作后不再出现

### 3.2 录入 `#/add`
1. `<input type="file" accept="image/*" capture="environment">` 拍照或选图
2. 图片经 canvas 压缩至最长边 ~1024px、JPEG 质量 0.7
3. 显示预览 + "识别中…"，调 AI 接口
4. 识别成功：自动填充表单（药名、效期日期选择器）
5. 识别失败/识别不出：表单留空，用户手动填写（照片保留）
6. 表单：药名（必填）、效期日期（必填，`<input type="date">`）、备注（选填）
7. 保存 → 照片 blob + 数据存 IndexedDB → 跳回首页

### 3.3 详情/编辑 `#/detail/:id`
- 大图查看
- 编辑药名/效期/备注
- 操作：「已扔掉 / 已用完」→ `status` 改为 `disposed`
- 「删除」→ 真删（含确认弹窗）

### 3.4 设置 `#/settings`
- API Base URL（默认 `https://open.bigmodel.cn/api/paas/v4`）
- API Key（存 localStorage）
- 模型名（默认 `glm-4v-flash`，免费模型，可改）
- 提前提醒天数（默认 30）
- API 直连说明：Key 只存在本机浏览器 localStorage，仅用户自己使用

## 4. 数据模型

IndexedDB，数据库 `medicine-box`，版本 1，单对象仓库 `medicines`（主键 `id`，自增）：

```js
{
  id: number,          // 主键自增
  name: string,        // 药名（必填）
  expiry: string,      // 效期 "YYYY-MM-DD"（必填）
  note: string,        // 备注（选填）
  photo: Blob,         // 压缩后的 JPEG
  createdAt: number,   // Date.now()
  status: "active" | "disposed"
}
```

设置项存 localStorage（key 前缀 `mb_`）：`mb_api_base`、`mb_api_key`、`mb_model`、`mb_remind_days`。

## 5. AI 识别流程

1. 压缩后图片转 base64
2. `POST {baseURL}/chat/completions`，OpenAI 兼容协议：
   ```json
   {
     "model": "<用户设置>",
     "messages": [{
       "role": "user",
       "content": [
         {"type": "image_url", "image_url": {"url": "data:image/jpeg;base64,..."}},
         {"type": "text", "text": "<prompt>"}
       ]
     }],
     "response_format": {"type": "json_object"}
   }
   ```
3. Prompt 要求（关键点）：
   - 从药品包装照片提取**药品名称**和**有效期**
   - 效期格式五花八门：`2027.05.10`、`EXP 2027/05`、`生产日期 2024.01 + 有效期36个月` → **一律换算为绝对日期 YYYY-MM-DD**
   - 只有年月（如 2027.05）→ 按该月最后一天算（2027-05-31）
   - 识别不出或无法换算 → 对应字段返回 null，不猜
   - 返回 `{"name": "...", "expiry": "YYYY-MM-DD" | null}`
4. 解析返回的 JSON（容错：剥离 markdown 代码围栏），填入表单
5. 任何失败（网络/鉴权/解析）→ 表单可手动填写，流程不中断

## 6. 提醒策略（v1）

选择网页形态时已接受系统级推送不可靠的取舍。v1 的提醒 = **打开即看见**：首页就是红橙绿仪表盘。

后续可加（非本期范围）：Android/桌面浏览器 Notification API 打开时弹临期汇总、日历订阅、完整 PWA 推送。

## 7. 文件结构

```
medicine-box/
  index.html   # 4 屏 UI + hash 路由 + 模板
  app.js       # IndexedDB 封装、效期状态计算、AI 调用、渲染与交互
  style.css    # 移动优先、大字号（≥16px，老人可读）
  test.html    # 纯逻辑自检页（引入 app.js 中的纯函数跑 assert）
```

无构建、无依赖、无框架。部署 = 把目录扔到任意静态服务器。

## 8. 错误处理

| 场景 | 处理 |
|---|---|
| AI 调用失败（网络/Key 无效/超时） | 行内提示原因，表单转手动填写，照片保留 |
| AI 返回非法 JSON | 剥围栏重试解析一次，仍失败转手动 |
| 药名/效期未填就保存 | 表单校验，标红必填项 |
| 照片加载失败 | 占位图（灰色药盒 emoji） |
| IndexedDB 不可用（隐私模式等） | 首页顶部横幅提示"存储不可用，请换浏览器或关闭隐私模式" |

## 9. 测试与验证

- `test.html`：对纯函数跑 assert ——
  - 效期状态计算（过期/临期/正常、剩余天数、边界：今天、提前天数当天）
  - AI 返回解析（正常 JSON、带围栏、null 字段、月份换算）
- 人工验证（Playwright 打开走查）：
  1. 无 Key 时手动录入一条 → 列表出现、状态颜色正确
  2. 填 Key 后拍照识别 → 表单自动填充
  3. 标记已扔 → 从首页消失
  4. 改提前提醒天数 → 分组随之变化

## 10. 非目标（明确不做）

- 云端同步 / 家庭多人共享（二期）
- 系统级推送通知（形态限制，v1 用"打开即看"代替）
- 用药提醒（吃药闹钟）— 本产品只管效期，不管服药
- 数量/批号/厂家等字段 — 最小够用，需要再加
- 多药箱分成员管理
